# Feature inventory of terminal coding-agent UIs (2026) and user sentiment

State as of 2026-10-21. Thirteen products: Claude Code (CC), Codex CLI (CX), Gemini CLI (GM), OpenCode (OC), Crush (CR), pi (PI), Amp (AMP), Cursor CLI (CUR), GitHub Copilot CLI (COP), Goose (GO), Aider (AID), Factory Droid (DR), Kiro CLI (KR). Official docs were fetched directly where possible; sentiment comes from Hacker News threads, GitHub issues, blog critiques and three 2026 surveys. Reddit could not be searched (the search tool reports reddit.com blocks its crawler), so Reddit sentiment is a gap.

## Feature matrix: feature by product

### Takeaway
All thirteen tools converge on one shape (streaming markdown transcript, collapsed tool cards, `/` palette, `@` file picker, `!` shell, Esc/Ctrl+C interrupt, resume picker, `/compact`, `/model`, MCP, headless mode), but they split sharply on four design axes: inline scrollback vs alternate-screen "fullscreen" rendering; permission prompts vs no prompts; whether rewind restores files; and whether multi-session/agent views live inside the TUI. The matrix below cites a URL key per cell; the legend maps keys to URLs. Cells marked "—" mean the feature was not found on the pages fetched (not proof of absence); "3P" marks a third-party source.

### Inferences
- Features present in roughly ten or more of thirteen products are table stakes for a new TUI: streaming markdown, `/` palette with completion, `@` file picker, `!` shell passthrough, Enter-submit with at least `Ctrl+J` newline plus a `/terminal-setup`-style helper for Shift+Enter, history recall with `Ctrl+R`, Esc/Ctrl+C interrupt with double-press-to-exit, collapsed tool cards with a `Ctrl+O`-style expand, a session resume picker, `/compact`, `/model`, MCP listing, headless/JSON mode, and a mode-cycling key (Shift+Tab in CC, GM, CUR, COP, DR, KR).
- The products split into "ask" (CC, OC, CR, COP, CUR, KR, GM, DR, GO) and "never ask, sandbox instead" (PI, AMP) camps; the "ask" camp has converged on a three-to-four option prompt: once / session or always with a tool-suggested pattern / no with feedback.
- File-restoring rewind is now common (CC snapshots, GM `/rewind` + `/restore`, COP `/undo` without git, OC git-based `/undo`), while Codex removed `/undo` and Kiro and pi fork the conversation only; this is a genuine differentiator, not table stakes.
- In-TUI multi-session management (CC agent view, OC 2.0 tabs/child sessions, COP `/fork` live, KR `/sessions` dashboard + crew monitor, DR Mission Control) arrived mostly in 2026 and is still contested in sentiment (see Sentiment section).

### Gaps
- Codex CLI's official pages for keyboard shortcuts and approval-mode cycling were not reachable (developers.openai.com redirects; `/docs/cli/features` 404); newline binding, `@` picker, `!` shell, and Shift+Tab remain unconfirmed from primary sources.
- Crush has no official keybinding page; the matrix relies on a third-party keymap page that claims derivation from Crush's default keymap.
- Goose's official command page does not list `/plan`/`/endplan`; third-party cheat sheets do. Amp's modes/permissions pages were only reachable through search snippets of the manual.
- No product page fetched documents reduced-motion support; `NO_COLOR` is documented only for Kiro (plus Copilot's `--no-color`).

## Input and composition: how products bind newline, paste, mentions, rewind, queueing and interrupt

### Takeaway
The de-facto standard is Enter to submit with `Ctrl+J` as the always-works newline, `Shift+Enter` where the terminal reports modified Enter (several tools ship a `/terminal-setup` to install it), and a backslash-Enter escape; large pastes collapse to a placeholder; `Esc` stops the turn and a double `Esc` on an empty prompt opens edit/rewind; and the 2026 trend is explicit "steer now vs queue for later" semantics (CC Ctrl+Enter, pi Alt+Enter, Amp Enter-Enter, Codex Tab vs Enter).

### Cited Findings
- Claude Code multiline: `\`+Enter works in all terminals; `Ctrl+J` "works in any terminal without configuration"; Shift+Enter native in iTerm2, WezTerm, Ghostty, Kitty, Warp, Apple Terminal, Windows Terminal — [Claude Code interactive mode](https://code.claude.com/docs/en/interactive-mode)
- Claude Code strips invisible Unicode (tag characters, bidi controls, zero-width spaces) on Enter and shows "Removed 3 invisible characters · review and press Enter to send" — [Claude Code interactive mode](https://code.claude.com/docs/en/interactive-mode)
- Claude Code queueing: Enter while working queues; queued messages are delivered "as soon as those tool calls finish, within the same turn"; `Ctrl+Enter` or `Ctrl+X Ctrl+S` sends now (v2.1.275+); `Up` from first row takes queued messages back; `Esc` interrupts and sends queued next — [Claude Code interactive mode](https://code.claude.com/docs/en/interactive-mode)
- Claude Code `Esc Esc`: clears a non-empty draft (saved to history), or opens the rewind menu when empty; `Ctrl+C` first press clears prompt, second exits; `Ctrl+D` needs a second press within 800 ms — [Claude Code interactive mode](https://code.claude.com/docs/en/interactive-mode)
- Claude Code `Ctrl+S` stashes/restores the prompt including pasted content and shell mode; `Ctrl+V`/`Alt+V` inserts an `[Image #N]` chip; `:` emoji shortcodes (v2.1.217+); `?` toggles a shortcut help panel; prompt suggestions as grey ghost text accepted with Tab/Right — [Claude Code interactive mode](https://code.claude.com/docs/en/interactive-mode)

### Inferences
- A newline chord that works everywhere (`Ctrl+J`) plus terminal-specific Shift+Enter with a setup command is now expected; relying on Shift+Enter alone is a documented support headache (aider's "no portable way", OpenCode's Windows Terminal workaround, Amp's tmux `extended-keys`, the wren.wtf complaint that Shift+Enter "doesn't insert a newline").
- The newest designs separate two intents while a turn runs: steer (inject into the current turn) and queue (wait for turn end). Claude Code, pi, Amp and Codex each expose both; Copilot and Gemini only queue.
- Double-`Esc` has become overloaded (clear draft, edit last message, open rewind) and each product resolves it differently; Droid even uses a triple `Esc`. A new TUI should pick one semantics and show a hint.

### Inferences
- The strongest preference drivers in the evidence are not individual widgets but (1) rendering stability (no flicker, scroll stays put, native copy/paste works), (2) provider/model freedom and token economy, (3) a permission model that neither nags nor is theatre, and (4) stability/trust (no crashes, no surprise daemons or auto-updates). Keybinding polish and pretty chrome are mentioned but rarely decisive.
- Complaints about alt-screen TUIs (lost scrollback, hijacked selection, cleared screen on exit) are as loud as complaints about inline-render flicker; a new TUI should offer both renderers or an alt-screen mode with explicit escape hatches, as Claude Code (`[`, `CLAUDE_CODE_DISABLE_MOUSE`), Codex (`/raw`) and OpenCode (`mouse:false`) now do.
- Because Reddit was unreachable, sentiment skews toward Hacker News and GitHub issues (complaint-heavy); the three surveys counterbalance with broad usage/affection numbers.

### Gaps
- No Reddit threads (r/ClaudeAI, r/ChatGPTCoding, r/LocalLLaMA) could be retrieved; their first-hand UI opinions are missing.
- Pragmatic Engineer's "most disliked tools" and the reasons respondents gave for preferring one terminal agent are behind a paywall and were not visible.
- No survey quantifies preference for specific UI features (e.g., plan mode vs rewind); feature-level preference is inferred from thread sentiment only.

## Emerging in 2026: what is new

### Takeaway
2026 brought five new UI categories to terminal agents: alternate-screen renderers with mouse support (Claude Code default for new users from May 6, 2026; Kiro TUI default; Codex `/tui`+`/raw`), in-TUI agent/session orchestration views (Claude agent view, Kiro crew monitor, Droid Mission Control, OpenCode 2.0 tabs and background subagents, Copilot `/fleet`), phone/web remote control of a local session (Claude Remote Control with QR, Copilot `/remote`, OpenCode `/pair`, Droid daemon), scheduled and looping tasks from the prompt (Claude `/schedule` and `/loop`, Copilot `/every` and `/after`, goose cron), and side-question overlays (`/btw` in Claude, Codex, Copilot, Droid). Voice push-to-talk also became common.

## Which features drive preference: table stakes vs differentiators

### Takeaway
Table stakes are the features present almost everywhere and whose absence is called out as "lacks the basics"; differentiators are the features users name when explaining a switch. The evidence says stability and rendering quality, permission ergonomics, rewind with file restore, steer-vs-queue semantics, and multi-session views are where products win or lose, while chrome (gradients, pets, animations) can hurt.

### Cited Findings
- "Lacks the basics" critique of a new TUI named: "the full suite of expected keybindings, tab completion, consistent scrollback" (jsnell) and missing up/down history (dgunay) — [HN 44736176](https://news.ycombinator.com/item?id=44736176)
- Switch reasons cited verbatim: performance and RAM (Claude→Codex, jmmv), "model and vendor freedom" (→OpenCode, scuff3d), low memory (OpenCode→Crush, Imustaskforhelp), stability (→pi, sauercrowd; away from Claude Code, hboon/tshaddox; away from OpenCode, Darkmoon_UK) — [HN 47460525](https://news.ycombinator.com/item?id=47460525)
- Users prefer OpenCode's per-tool prompts and per-project memory of permissions (spopejoy) while others want a Claude-style auto mode (moretti) — [HN 50094994](https://news.ycombinator.com/item?id=50094994)
- "I do miss support for permissions, MCP and perhaps Todos and a server mode" (solarkraft) lists what a minimal agent must add back — [HN 47143754](https://news.ycombinator.com/item?id=47143754)
- Codex users asking for `/rewind` after `/undo` was removed shows file-restoring rewind is valued — [openai/codex #9618](https://github.com/openai/codex/discussions/9618)
- Hamel's named favourites in Amp are server-stored threads, handoff, queued messages and editing prior messages — [hamel.dev](https://hamel.dev/notes/coding-agents/amp.html)
- Demand for tabs/sidebars/subagent panels is visible in OpenCode feature requests — [#12548](https://github.com/anomalyco/opencode/issues/12548), [#57097](https://github.com/anomalyco/opencode/issues/57097)
- Survey-level: Claude Code most used and most loved (46%) — [Pragmatic Engineer](https://newsletter.pragmaticengineer.com/p/ai-tooling-2026); 39% at work per JetBrains — [JetBrains Research](https://blog.jetbrains.com/research/2026/08/ai-coding-agent-adoption-2026/)

### Inferences
- Table stakes (present in ≥10/13 products or named as "basics"): streaming markdown with syntax-highlighted code; collapsed tool cards with one expand key; `/` palette with fuzzy completion and argument hints; `@` fuzzy file picker; `!` shell passthrough; Enter submit + `Ctrl+J` newline + Shift+Enter setup helper; large-paste placeholder; image paste; prompt history with `Ctrl+R`; `Esc` interrupt, `Ctrl+C` double to exit, `Ctrl+D`; a permission prompt with once/session/always-pattern/deny-with-reason; Shift+Tab mode cycle incl. plan mode; `/compact` plus a visible context gauge; `/model` picker with effort; `/status`/`/doctor`; MCP list with connect state; session resume picker with titles; `/init` project memory file; headless JSON/stream mode; vim mode; theme choice incl. a colour-blind/ANSI option; `NO_COLOR` respect; emacs-style editing keys.
- Differentiators (uneven across products, named in switch reasons): flicker-free alt-screen renderer with mouse and escape hatches; rewind that restores files (snapshots) with "summarize from here"; explicit steer-now vs queue-later keys and take-back; `/btw` side questions; in-TUI multi-session view with peek/attach and worktree isolation; live diff panel with per-turn views and "ask about this file"; classifier/auto mode plus autonomy dial; remote control from phone with QR; scheduled/looping tasks from the prompt; session sharing/export links; sound/desktop notifications per event; auto-generated session names and recaps; low memory/CPU footprint; provider/model freedom with local models.
- Anti-features (sentiment-negative): heavy chrome and animations, background daemons/auto-updates without consent, hijacked copy/paste, screen clear on exit, nag messages, permission "Always" that silently persists broad prefixes.

### Gaps
- No controlled study ranks feature importance; the table-stakes/differentiator split is an inference from prevalence counts in the matrix and from switch reasons in threads.
