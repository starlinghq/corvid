# Making a terminal UI solid: testing, accessibility, terminal-state recovery, long sessions and huge outputs (state as of 2026-10-21)

Scope: notes for the Corvid TUI design (local-first .NET 10 agent, Linux first, tests today run in-process through Spectre.Console `TestConsole`; CI is an Arch Linux self-hosted runner without root). Four key questions, each with Takeaway / Cited Findings / Inferences / Gaps. Every finding carries a URL; where only a mirror or secondary source was reachable it is marked as such. "Open"/"closed" states are as read on 2026-10-21.

---

## Key question 1 — TUI testing tools and techniques (and what is usable from .NET)

### Takeaway
Every leading agent CLI tests its UI mostly in-process against an in-memory backend plus text snapshots (Codex: ratatui `TestBackend` + `insta`, and a `vt100`-emulator backend for the "write history into scrollback" path; Gemini CLI: Ink rendered into `@xterm/headless`; OpenTUI/OpenCode: `createTestRenderer`; Textual: `run_test()`/Pilot + SVG snapshots; Bubble Tea: `teatest` golden files; Terminal.Gui: a fake driver), and keeps real-PTY end-to-end tests as a thin layer (Microsoft's `tui-test`, rewritten in 2026 as a multi-backend engine with a CLI that drives any binary). The .NET equivalents exist today: `XTerm.NET` 3.0 (headless VT emulator, MIT, net10.0) turns an output byte stream into a screen grid for assertions, `Porta.Pty` 2.2.3 gives a PTY, and `/dev/ptmx` needs no root — but CI steps have no TTY unless the test allocates one.

### Cited Findings

#### How the leading agent CLIs and TUI frameworks test their UIs

#### Testing input decoding deterministically (kitty keyboard, paste, mouse)

#### Resize robustness and fuzzing
- Codex #54979 (open, filed 2026-10-18): panic "index outside of buffer: the area is Rect { x: 0, y: 0, width: 80, height: 24 } but index is (0, 36)" when the terminal shrinks before SIGWINCH is handled; `screen_size_for_event()` returned the cached `last_known_screen_size` for key/mouse/paste events while `Tui::draw()` re-queried and resized the buffer, so layout used a stale 37-row size; proposed fixes: re-query size on input events, or clamp render areas to `frame.area()` — [codex #54979](https://github.com/openai/codex/issues/54979)

- Claude Code #1495 (open since 2025-06-02): rendering glitches under tmux / rapid resolution changes — [claude-code #1495](https://github.com/anthropics/claude-code/issues/1495)

### Inferences
- The common architecture is a three-layer test pyramid: (1) pure view/layout tests against an in-memory cell buffer with text snapshots at several widths; (2) "byte-level" tests that feed the renderer's real escape output into a VT emulator and assert on the emulated grid/scrollback (Codex's vt100 backend, Gemini's xterm-headless streams) — this is the only layer that catches scroll-region, cursor-save and wrapping bugs; (3) a handful of real-PTY smoke tests. For Corvid in .NET: layer 1 can keep `TestConsole`-style string capture only if the renderer has its own cell buffer; layer 2 maps directly onto `XTerm.NET` (feed `ReadOnlySpan<byte>`, read `GetLine(row).TranslateToString()`); layer 3 can use `Porta.Pty` from xUnit, or the language-agnostic `tui-test` CLI against the published Corvid binary.
- Input decoding should be tested the crossterm way: a parser that accepts arbitrary byte chunks with a three-way result (need-more / error / event), fed with fixture byte strings for kitty CSI-u (press/repeat/release, modifiers, caps/num lock), bracketed paste split across reads, SGR mouse, focus events, OSC reply strings (cursor position, OSC 10/11 colours, DA1) and the lone-ESC timeout. Split-at-every-byte-boundary runs make this deterministic and cheap.
- On the Arch self-hosted runner, PTY tests need only `/dev/pts` mounted (standard) — `openpty`/`forkpty` is unprivileged; the risk is the runner process itself having no controlling TTY, which the PTY library sidesteps because the test owns the master side. Hosted-runner behaviour (no TTY) should still be handled by skipping PTY tests when `posix_openpt` fails.
- Resize fuzzing is cheap once layout is a pure function of (model, width, height): property-test random sizes including 0/1 columns and heights smaller than the input box, assert "no exception and every write inside the buffer" (the exact failure in Codex #54979), and replay recorded resize sequences through the emulator.

### Gaps
- Claude Code's own test approach is not public.
- Terminal.Gui's FakeDriver API and whether it exposes a cell grid for assertions could not be read from official docs (the v2 drivers doc URL 404s; GitHub code search was rate-limited); the `Tests/README` only places such tests in `UnitTests.Legacy`.
- `XTerm.NET` has no published conformance results (vttest/esctest) and a small community (39 stars); its claim list is broad but unverified here.
- Last-commit dates for `microsoft/tui-test` and `microsoft/vs-pty.net` were not visible; `tui-test` 0.1.0 is weeks old.
- No primary source on fuzzing TUIs with random resize events was found.

## Key question 2 — Accessibility: what screen reader users need, documented failures, and colour/motion conventions

### Takeaway
Screen reader users describe the same failure in every Ink/ratatui agent CLI: the "smart" TUI treats the terminal as a 2-D grid, so spinners, timers and per-keystroke full re-renders teleport the hardware cursor and spam the reader (NVDA can freeze), while linear output in scrollback with a stable cursor is what works. Claude Code's opt-in `--ax-screen-reader` mode (v2.1.181, July 2026) is the most complete written spec of a fix: flat labelled lines, no redraws of unchanged content, static spinners, numbered menus, cursor parked on the input caret, bell on turn end, OSC 133 marks; Gemini CLI has a plain-text `--screen-reader` flag; Codex has no mode but auto-detects a screen reader once (AT-SPI/VoiceOver/SPI_GETSCREENREADER) and turns animations off. No tool auto-enables a screen-reader mode; colour follows `NO_COLOR`/`FORCE_COLOR`/TTY detection; background detection via OSC 11 is done by Gemini (polled every 60 s) but not Claude Code; there is no cross-tool reduced-motion environment variable.

### Cited Findings

#### What screen reader users report (primary issues) and what projects did
- Claude Code #11002 (opened 2025-11-04 by a blind developer using NVDA/JAWS/Narrator): screen readers speak odd characters (`|`, partial Unicode), token streaming and spinner updates that rewrite the same line make the reader "freeze, skip lines, or stop responding", daily terminal lockups, `/config` relies on Unicode glyphs, the input line re-renders on every keystroke, the thinking status bar redraws every few seconds, permission prompts use arrow-key widgets; request: a `--screen-reader` flag that disables spinners/colour/animation and emits plain linear text. Anthropic's georgez-a11y announced `claude --ax-screen-reader` in v2.1.181 (2026-07-01): plain linear text, `you:`/`claude:` labels, numbered menus, `y`/`n` shortcuts, bell on turn completion, frozen elapsed-time line; released with docs 2026-07-20; closed completed 2026-07-21. - "The text mode lie: why modern TUIs are a nightmare for accessibility" (Casey Reeves, 2026-01-05; Speakup on Linux, NVDA on Windows): the cursor "teleporting" to update timers, "Responding…" timers producing constant announcements mixed with fragments of history, full re-render of the conversation on every keystroke or paste that "can crash NVDA", echo lag up to 10 s with large history in single-threaded Ink; older apps did it right — nano/vim let users hide the cursor, menuconfig keeps a strict single-column focus, irssi uses VT100 scrolling regions instead of redrawing; recommendations: guarantee a hide-cursor/"no-cursor" or headless mode, avoid aggressive redrawing for spinners/timers, keep the cursor pinned to the active area, use scrolling regions instead of full-screen diffing, prefer a linear stream; cites gemini-cli #3435, #11305 and #1553 (closed by a stale bot — "hiding evidence") — [xogium.me](https://xogium.me/the-text-mode-lie-why-modern-tuis-are-a-nightmare-for-accessibility); [OSnews coverage](https://www.osnews.com/story/144892/the-text-mode-lie-why-modern-tuis-are-a-nightmare-for-accessibility/)

- Google's CHI 2021 paper "Accessibility of Command Line Interfaces" (two studies, 12 developers using screen readers) concludes that CLIs "have their own set of accessibility issues — the most important being CLIs are unstructured text interfaces" — [research.google](https://research.google/pubs/accessibility-of-command-line-interfaces/); [ACM DOI](https://dl.acm.org/doi/10.1145/3411764.3445544). A mailing-list summary lists its recommendations as: HTML version of docs; a way to convert long outputs to another accessible format; document each command's output structure; a way to convert tables; status/progress for every command; progress indicators that work with screen readers; error messages understandable when read aloud (secondary; the ACM full text was not reachable) — [TeX Hour post](https://email.esm.psu.edu/pipermail/macosx-tex/2022-February/058138.html)
- AFB AccessWorld (Fall 2026, Aaron Preece): blind developers found the ChatGPT desktop app with Codex "quite accessible"; in very long conversations screen reader focus sometimes jumps to an earlier message — the article does not cover CLI tools — [afb.org](https://afb.org/aw/fall2026/diy-accessibility-vibe-coding)

#### The most detailed written spec of a screen-reader mode (Claude Code docs)
- Enable: `claude --ax-screen-reader`, `CLAUDE_AX_SCREEN_READER=1`, or `"axScreenReader": true`; precedence flag > env > setting; `CLAUDE_AX_SCREEN_READER=0` forces off; first line printed `[Screen Reader Mode: on via flag|env|settings]` — [Claude Code accessibility](https://code.claude.com/docs/en/accessibility)
- Output: flat text; no box-drawing chrome; no colour-only cues; "No redraws of content that hasn't changed. Progress spinners render as static text"; tables as `Header: value` sentences; diffs as plain `+`/`-` lines; everything stays in scrollback; the `tui` setting is ignored (classic scrolling renderer, not fullscreen); 3 s quiet period after the confirmation line (`CLAUDE_AX_STARTUP_QUIET_MS`); labels `you:`, `claude:`, `thinking:`, `tool:`, `tool error:`, `error:`, `warning:`, `Permission Required:`, `Cost:` (searchable in scrollback); "Claude Code keeps the terminal cursor on the input caret"; typing/backspace at end of line writes only the changed characters; deleted text is announced for Ctrl+W/Alt+D/Ctrl+U/Ctrl+K; Shift+Tab mode changes announced once; NVDA+6 tip to stop the review cursor following the terminal cursor; OSC 133 marks at turn boundaries (iTerm2 Cmd+Shift+Up, VS Code Ctrl/Cmd+Up, Windows Terminal `scrollToMark`; not emitted in WezTerm; macOS Terminal ignores them); menus become numbered lists with a `Select with numbers` prompt; yes/no prompts take `y`/`n`; bell when a reply finishes, a prompt needs an answer, or a tool ran > 5 s; known limitations: no auto-detection of a running screen reader, `claude attach` uses the alternate screen, costs only at exit — [Claude Code accessibility](https://code.claude.com/docs/en/accessibility)
- Tunables: `CLAUDE_AX_PREPARK_MS` (ms to hold the cursor at the start of the line before writing a new/changed line; default 0, was 50 before v2.1.287, cap 5000), `CLAUDE_AX_STARTUP_QUIET_MS` (default 3000, cap 600000), `CLAUDE_CODE_ACCESSIBILITY=1` (keep the native terminal cursor visible and disable the inverted-text cursor so magnifiers like macOS Zoom can track it), `prefersReducedMotion` setting ("Reduced or no spinners, shimmer, and other animations"), `theme` incl. `dark-daltonized`/`light-daltonized`, `preferredNotifChannel: "terminal_bell"` — [Claude Code env vars](https://code.claude.com/docs/en/env-vars); [Claude Code accessibility](https://code.claude.com/docs/en/accessibility)
- Reduced-motion friction in Claude Code: `prefersReducedMotion: true` reportedly did not stop the blinking ⏺ indicator (#39224, marked resolved), it is not discoverable at runtime and needs a restart (#57237), and the rotating "whimsical" spinner words cannot be made static (#64098, #71483) — [claude-code #39224 (via claudeissues mirror)](https://github.com/anthropics/claude-code/issues/39224); [#57237](https://github.com/anthropics/claude-code/issues/57237); [#64098](https://github.com/anthropics/claude-code/issues/64098); [#71483](https://github.com/anthropics/claude-code/issues/71483)

#### Colour conventions, contrast and background detection
- `NO_COLOR`: when "present and not an empty string (regardless of its value)" software that adds ANSI colour by default should not; "per-instance command-line arguments should override the NO_COLOR environment variable"; page last updated 2026-10-12 — [no-color.org](https://no-color.org/)
- `FORCE_COLOR`: "When this variable is present and not an empty string (regardless of its value), it should force the addition of ANSI color" (meant to override CI/non-TTY detection); the reference example checks `NO_COLOR` first, then `FORCE_COLOR` — [force-color.org](https://force-color.org/)
- Command Line Interface Guidelines: disable colour when stdout or stderr is not a TTY (check separately), when `NO_COLOR` is set, when `TERM=dumb`, or with `--no-color`; consider `MYAPP_NO_COLOR`; `FORCE_COLOR` "to enable it and ignore the detection logic"; "If stdout is not an interactive terminal, don't display any animations" — [clig.dev](https://clig.dev/)
- Gemini CLI: `ui.autoThemeSwitching` (default `true`, "Switches between light and dark themes based on terminal background color"), `ui.terminalBackgroundPollingInterval` (default 60 s), `ui.useBackgroundColor`, `tools.shell.showColor` — [Gemini CLI settings](https://geminicli.com/docs/cli/settings/)
- Claude Code does not detect the background: #36152 asked for `theme: "auto"` via OSC 11 (`\e]11;?\a`, supported by Ghostty, iTerm2, Kitty, Alacritty, WezTerm, Windows Terminal) and was closed as a duplicate of #2990/#33899 — [claude-code #36152](https://github.com/anthropics/claude-code/issues/36152); #49848 reports the user-turn block rendered near-black on light themes (Ghostty 1.2.3, Claude Code 2.1.112), labelled `area:a11y`, closed "not planned" for inactivity 2026-05-25; the related #49839 covers dim (bright-black) text unreadable on light themes — [claude-code #49848](https://github.com/anthropics/claude-code/issues/49848)
- How to query safely: `terminal-colorsaurus` 1.0.3 (2026-09-08) sends OSC 10/11 and a DA1 (`CSI c`) request in the same write; because terminals answer in order, a DA1 reply arriving before any colour reply proves the OSC query is unsupported, so no timeout is needed in the common case; default timeout 1 s for the rest (SSH latency, terminals that ignore DA1); Windows supported from Windows Terminal 1.22; sends nothing when `TERM=dumb`; restores raw mode even on error/panic — [terminal-colorsaurus](https://docs.rs/terminal-colorsaurus/latest/terminal_colorsaurus/); [feature_detection module](https://docs.rs/terminal-colorsaurus/latest/terminal_colorsaurus/feature_detection/index.html)
- Codex probes the terminal at startup (cursor position, default colours, keyboard-enhancement support, SSH status) with a timeout and falls back to empty results — [tui.rs](https://github.com/openai/codex/blob/main/codex-rs/tui/src/tui.rs)
- Query replies are an input hazard: ratatui's spawn-vim recipe warns that vim's own background-colour query is answered on stdin and "Crossterm consumes it, so ANSI RGB values can appear in the TUI afterward" — [ratatui spawn-vim](https://ratatui.rs/recipes/apps/spawn-vim/); kitty < 0.47.3 echoed attacker bytes (including newlines) in OSC 21 colour-query replies into the shell (CVE-2026-54057) and kitty < 0.47.0 allowed command execution via crafted escape codes that trigger error replies (CVE-2026-42850) — [CVE-2026-54057 (Mend, secondary)](https://mend.io/vulnerability-database/CVE-2026-54057/); [CVE-2026-42850 (OSV)](https://osv.dev/vulnerability/CVE-2026-42850)
- Textual's `ansi_color` reactive: `True` uses the terminal's ANSI palette, `False` converts colours to RGB, `None` defers to the theme — i.e. a framework-level switch between "respect the user's palette" and "control contrast yourself" — [Textual App API](https://textual.textualize.io/api/app/)
- Claude Code ships `dark-daltonized`/`light-daltonized` themes as its colour-blind accommodation — [Claude Code accessibility](https://code.claude.com/docs/en/accessibility). Standard references for contrast and colour-blind-safe palettes (not re-fetched in this pass): WCAG 2.2 SC 1.4.3 contrast minimum 4.5:1 — [w3.org](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html); Okabe–Ito palette — [jfly.uni-koeln.de/color](https://jfly.uni-koeln.de/color/)
- Terminal "jump between prompts" support that a screen-reader mode can piggy-back on: OSC 133 defines "Input, Output and Prompt zones"; WezTerm exposes ScrollToPrompt and output selection on top of it and points to Per Bothner's semantic-prompts proposal — [WezTerm shell integration](https://wezterm.org/shell-integration.html); [semantic-prompts proposal (fetch blocked by anti-bot page)](https://gitlab.freedesktop.org/Per_Bothner/specifications/-/blob/master/proposals/semantic-prompts.md)

### Inferences
- The minimum viable accessible mode, synthesised from the Claude Code spec and the complaints: (1) a linear "stream" renderer that only ever appends and never rewrites lines other than the current input line; (2) static text in place of spinners (one line "working…", updated at most on state change); (3) every message block prefixed by a spoken-style label; (4) the hardware cursor parked on the input caret, with no fake inverted-cell cursor; (5) menus as numbered lists answered with digits and y/n; (6) bell (or OSC 9/777 notification) on completion and on prompts; (7) OSC 133 marks per turn; (8) tables and diffs flattened. All of this is cheaper to build on an inline/scrollback renderer than on an alternate-screen renderer, which is why Claude Code forces the classic renderer in this mode.
- Auto-detection is feasible on Linux via AT-SPI D-Bus (Codex's probe) and could pre-select reduced motion, but no tool auto-enables full screen-reader mode — doing so silently is risky (false positives, AT-SPI `IsEnabled` also covers other assistive tools); a startup hint plus an explicit flag/env/setting is the established pattern.
- Reduced motion has no cross-tool environment variable; the practical convention is a settings key plus a runtime toggle, honoured for spinners, shimmer and blinking indicators, and the same switch should stop the timer-driven redraw loop entirely (Claude Code #78969 shows otherwise idle sessions burn CPU).
- Colour: implement the `NO_COLOR`/`FORCE_COLOR`/`TERM=dumb`/non-TTY rules; prefer the terminal's own 16-colour palette for most UI so user themes carry contrast; where a fixed RGB background is unavoidable (user-turn blocks, selection), query OSC 11 with the DA1 guard at startup (and re-check on resume/at intervals as Gemini does) and pick light/dark variants; never write the query reply bytes anywhere but the input parser.

### Gaps
- No guidance from accessibility organisations specific to terminal applications beyond the Google paper was found; W3C/WCAG has no TUI profile.
- How terminal emulators expose text to screen readers (Windows Terminal UIA, VoiceOver in Terminal.app, Orca with VTE) was not researched from primary sources here.
- The Google paper's recommendation list comes from a secondary summary; the ACM full text was not reachable.
- Whether Gemini's screen-reader mode changes anything beyond "plain text" (menus, cursor, bell) is not documented on the settings page; the implementing PR (#6653) was not read.

## Key question 3 — Terminal-state recovery (exit, crash, signals, suspend/resume, child processes)

### Takeaway
Practice has converged on one idempotent "restore" routine that is run from every exit path — normal exit, the panic/unhandled-exception hook (installed *before* the terminal is initialised), SIGINT/SIGTERM handlers, and SIGTSTP before re-raising the signal with the default handler — and re-applied after SIGCONT and after any child process has had the terminal. The sequences that must be undone are: kitty keyboard flags (pop, and on process exit also `CSI < u` clear-all), mouse and focus reporting, bracketed paste, synchronized-output, the alternate screen, cursor visibility/style, and finally cooked mode via the saved termios. The known gaps are races, not missing code: Codex still leaks kitty key-release fragments into the shell on Ctrl-C/Ctrl-D (#24026, #31865 open) and only fixed Ctrl-Z in Oct 2026 by waiting for a confirmed SIGCONT; Claude Code left the alternate screen active on suspend until 2.1.266; and shells may restore their own termios after SIGCONT, so cached "raw mode is on" state must not be trusted.

### Cited Findings

#### Normal exit and panics/unhandled exceptions
- Ratatui's recipe installs a panic hook that takes the original hook, restores the terminal (`disable_raw_mode()`, `LeaveAlternateScreen`), ignores restore errors "since the app is already panicking", and then calls the original hook; "Install the panic hook before initializing the terminal" — [ratatui panic hooks](https://ratatui.rs/recipes/apps/panic-hooks/). `ratatui::init()` enables raw mode, enters the alternate screen and "Installs a panic hook that restores the terminal before the program panics"; it advises calling `init` after installing any other panic hooks so the terminal is restored before they run — [docs.rs ratatui::init](https://docs.rs/ratatui/latest/ratatui/fn.init.html)
- crossterm: `PushKeyboardEnhancementFlags` "should be paired with `PopKeyboardEnhancementFlags` at the end of execution" (supported by kitty, foot, WezTerm, alacritty, notcurses, Neovim, Kakoune, dte) — [docs.rs PushKeyboardEnhancementFlags](https://docs.rs/crossterm/latest/crossterm/event/struct.PushKeyboardEnhancementFlags.html); raw mode (no echo, no line buffering, no signal keys, no newline post-processing) is toggled with `enable_raw_mode`/`disable_raw_mode` and the docs do not restore it automatically; commands include `EnterAlternateScreen`/`LeaveAlternateScreen`, `BeginSynchronizedUpdate`/`EndSynchronizedUpdate`, `EnableLineWrap`, `SetTitle` — [docs.rs crossterm::terminal](https://docs.rs/crossterm/latest/crossterm/terminal/index.html)
- Codex's real implementation: `init()` requires stdin and stdout to be terminals, arms a `TerminalInitializationGuard` (disarmed only on success), then `set_modes()` = Windows VT processing, `EnableBracketedPaste`, `enable_raw_mode()`, `keyboard_modes::enable_keyboard_enhancement`, `EnableFocusChange` (non-Windows), then `set_panic_hook()`; `restore_common()` undoes alternate-screen state, disables bracketed paste and focus change, disables raw mode when asked, restores the Windows input mode, resets the cursor style and shows the cursor; `restore()` uses `KeyboardRestore::PopStack`, while `restore_after_exit()` uses `KeyboardRestore::ResetAfterExit`, finishes the stderr guard and clears terminal program status; the panic hook wraps the previous hook, calls `restore_after_exit()` (errors ignored) and then the original hook; `recover_after_caught_panic()` re-runs `set_modes()`, invalidates cursor/viewport state and re-enters the alternate screen if needed; a `TerminalStderrGuard` keeps stray stderr writes out of the inline viewport — [tui.rs](https://github.com/openai/codex/blob/main/codex-rs/tui/src/tui.rs)
- Codex keyboard flags: base `DISAMBIGUATE_ESCAPE_CODES | REPORT_ALTERNATE_KEYS` (`CSI > 5 u`), plus `REPORT_EVENT_TYPES` (`CSI > 7 u`) unless excluded; never `REPORT_ALL_KEYS_AS_ESCAPE_CODES`; per-screen restore sends a pop plus `DisableModifyOtherKeys` (`CSI > 4;0 m`); the process-exit path sends pop, then the clear-all reset `ESC [ < u`, then `DisableModifyOtherKeys` — described as the stronger reset "so the parent shell doesn't inherit enhanced key reporting if the terminal misses the normal pop"; the legacy Windows API path reports these commands as unsupported — [keyboard_modes.rs](https://github.com/openai/codex/blob/main/codex-rs/tui/src/tui/keyboard_modes.rs)
- The kitty protocol itself: push flags with `CSI > flags u`, pop with `CSI < u` "at exit, or just before leaving the alternate screen"; main and alternate screens "must maintain their own, independent, keyboard mode stacks"; popping an empty stack resets all flags; terminals should bound the stack; if a program exits without clearing the mode the shell stays affected, but Enter/Tab/Backspace still send legacy bytes so the user can type `reset` — [kitty keyboard protocol](https://sw.kovidgoyal.net/kitty/keyboard-protocol/)
- Known gap — leaked key-release packets: Codex #24026 (open, 2026-05-22): after exit the shell prints `9;1:3u`, `9;5:3u`, `00;5u00;5:3u` in VS Code over Remote-SSH, Ghostty, native kitty and iTerm2; Ctrl+C/Ctrl+D leak, `/quit` and `/exit` do not; diagnosis: Codex acts on the key *press* and tears down while the matching *release* event is still unread, so resetting keyboard reporting cannot discard already-queued input; dropping `REPORT_EVENT_TYPES` only changes the fragment to `9;5u`; a proposed fix drains stdin byte-by-byte until the matching release arrives (5 s fallback) but can swallow type-ahead — [codex #24026](https://github.com/openai/codex/issues/24026); #31865 (open): zsh tries to execute `9;5:3u` after Ctrl-C in kitty; `reset` or `printf '\033[<10u'` recovers — [codex #31865](https://github.com/openai/codex/issues/31865)
- Bubble Tea: `Program.Run` recovers panics unless `WithoutCatchPanics()` ("the terminal may be left in an unusable state"); `recoverFromPanic` sends `ErrProgramPanic`, calls `shutdown(true)` (kill: skips the final frame) and prints the panic and stack with `\r\n` line endings (plus a `bubbletea-panic-<timestamp>.log` when `TEA_DEBUG`); goroutine panics go through `recoverFromGoPanic`; `shutdown` cancels the context, closes the input reader, stops the renderer and calls `restoreTerminalState`, which flushes queued commands and applies the saved termios via `term.Restore` to the input and output TTYs; `Kill()` "stops the program immediately and restores the former terminal state"; bracketed paste and mouse are disabled automatically on quit — [tea.go](https://github.com/charmbracelet/bubbletea/blob/main/tea.go); [tty.go](https://github.com/charmbracelet/bubbletea/blob/main/tty.go); [pkg.go.dev bubbletea](https://pkg.go.dev/github.com/charmbracelet/bubbletea). Bubble Tea v2.0.9 (Aug) shipped a "kitty keyboard stack restore on exit" fix and v2.1.0 (Oct 2026) fixed a "signal goroutine deadlock on shutdown" and 0x0 terminal sizes — [bubbletea releases](https://github.com/charmbracelet/bubbletea/releases)
- Ink: the constructor registers `unmount` with `signal-exit`; `unmount()` flushes/cancels throttled renders, does a final render, restores the patched console, unmounts React, then `finishUnmount` disables the kitty keyboard protocol (`ESC [ < u`) if it was enabled, calls `log.done()`, writes `exitAlternativeScreen` + `showCursorEscape` when on the alternate screen (alternate-screen content "is disposable by design"), and frees the Yoga root; raw mode and bracketed paste are owned by the App component, whose cleanup restores raw mode — [ink.tsx](https://github.com/vadimdemedes/ink/blob/master/src/ink.tsx); `alternateScreen` is ignored when stdout is not a TTY; `suspendTerminal()` turns raw mode off, shows the cursor, exits the alternate screen, then restores Ink's state and redraws — [Ink README](https://github.com/vadimdemedes/ink)
- Gemini CLI #27290: in non-interactive mode `setupStdinCancellation()` enabled raw mode but restored it only in a `finally`, so an early exit left the terminal in raw mode ("feels broken" until `reset`/`stty sane`); proposed `process.on('exit')` idempotent fallback; closed "not planned" for lack of response — [gemini-cli #27290](https://github.com/google-gemini/gemini-cli/issues/27290); #29424 "Node process hangs on session exit, preventing terminal from returning to shell prompt" (closed) — [gemini-cli #29424](https://github.com/google-gemini/gemini-cli/issues/29424)
- User-side fallbacks: `reset` (tset) sets cooked and echo modes, turns off cbreak/raw, turns on newline translation, restores special characters, and sends the terminal's reset strings; the man page says to type `<LF>reset<LF>` because carriage return "may no longer work in the abnormal state" and the terminal "will often not echo the command" — [tset(1)](https://invisible-island.net/ncurses/man/tset.1.html)
- Claude Code's fullscreen renderer has crash-loop protection: a session counts as "started successfully" once it drew its first frame and stayed up 10 s or exited via `/exit`, Ctrl+C or Ctrl+D; after one failed start the next session uses the classic renderer and prints a notice; after two, it stays classic until an update or an explicit `/tui fullscreen`; counts are per version and reset on success — [Claude Code fullscreen](https://code.claude.com/docs/en/fullscreen)

#### SIGINT / SIGTERM / SIGHUP
- ncurses installs `handle_SIGINT` for both SIGINT and SIGTERM (only if the application left them at default): a `cleanup_nested` guard, ignore further signals, `endwin()` on each screen, then `_exit(EXIT_FAILURE)`; the comment admits "Much of this is unsafe from a signal handler. But we'll _try_ to clean up the screen and terminal settings on the way out"; `lib_tstp.c` installs no SIGHUP handler — [ncurses lib_tstp.c (GitHub mirror)](https://github.com/mirror/ncurses/blob/master/ncurses/tty/lib_tstp.c)
- Bubble Tea's `handleSignals` listens only for SIGINT (→ `InterruptMsg`, `Run` returns `ErrInterrupted`) and SIGTERM (→ `QuitMsg`); `WithoutSignalHandler()` hands signals to the app — [tea.go](https://github.com/charmbracelet/bubbletea/blob/main/tea.go)
- clig.dev: on Ctrl-C "exit as soon as possible", print a message before cleanup, bound cleanup with a timeout, let a second Ctrl-C skip cleanup and say so ("Gracefully stopping... (press Ctrl+C again to force)"), and "expect to be started in a situation where clean-up has not been run" — [clig.dev](https://clig.dev/)
- A wedged main thread defeats SIGTERM: Claude Code #21567 reports SIGTERM often has no effect during a renderer CPU spin, forcing `kill -9` — [claude-code #21567](https://github.com/anthropics/claude-code/issues/21567)

#### SIGTSTP (Ctrl-Z) and SIGCONT
- ncurses `handle_SIGTSTP`: first checks `tcgetpgrp` ("if not, an interactive shell may already have taken ownership of the tty"), saves program modes (`def_prog_mode`), blocks SIGALRM/SIGWINCH/SIGTTOU, calls `endwin()`, unblocks SIGTSTP, sets `SIG_DFL` and `kill(getpid(), SIGTSTP)`; on SIGCONT it restores the handler, `flushinp()`, re-saves shell modes with `def_shell_mode()` so tty changes the user made while suspended stick, and relies on `doupdate()` to "restore the program-mode tty state, and issue enter_ca_mode if need be"; the file warns the code "is fragile" because OSs differ on restarting interrupted syscalls (`SA_RESTART`) — [ncurses lib_tstp.c](https://github.com/mirror/ncurses/blob/master/ncurses/tty/lib_tstp.c)
- Bubble Tea: `SuspendMsg` → `suspend()` = `releaseTerminal(true)` (ignore signals, cancel reader, stop renderer, restore terminal) → `suspendProcess()` = `signal.Notify(c, SIGCONT)`, `syscall.Kill(0, SIGTSTP)` (whole process group), block on `<-c` → `RestoreTerminal()` (re-init input reader and renderer, `checkResize` for size changes made while away, flush queued output) → `ResumeMsg` — [tea.go](https://github.com/charmbracelet/bubbletea/blob/main/tea.go); [tty_unix.go](https://github.com/charmbracelet/bubbletea/blob/main/tty_unix.go)
- Codex: `reapply_raw_mode_after_resume()` disables and re-enables raw mode because "a shell can restore saved terminal settings after SIGCONT, which can leave crossterm's cached raw-mode state stale"; `TuiEvent::Resume` refreshes geometry "because resize events are not delivered while suspended"; the cursor row is saved before suspending so Ctrl-Z can place the cursor correctly — [tui.rs](https://github.com/openai/codex/blob/main/codex-rs/tui/src/tui.rs). PR #51192 "Wait for SIGCONT when resuming the TUI" (merged 2026-10-05) installs a temporary SIGCONT handler, unblocks it, sends SIGTSTP, waits with a bounded timeout for confirmation before restoring state, then restores the previous handler/mask and reapplies terminal modes even when suspension fails — [codex PR #51192](https://github.com/openai/codex/pull/51192); it addresses #31013 (kitty 0.32.2: after Ctrl-Z the prompt shows `2::121;133:3u` and every key adds more; fixed in CLI 0.162.1 per the maintainer) — [codex #31013](https://github.com/openai/codex/issues/31013)
- Claude Code #78690 (Alacritty on sway, 2.1.212): after Ctrl-Z, raw mode, mouse reporting and bracketed paste stayed on; a middle-click paste then wedged the terminal; `reset`/`stty sane` typed blind did not recover because the emulator stopped servicing input; `kill -CONT` bounced the process back to stopped via SIGTTIN; recovery needed `kill -9` of Alacritty; expected behaviour "like vim, less, tmux, or htop": catch SIGTSTP, restore modes, re-raise, re-arm on SIGCONT; closed as a duplicate of #77752 — [claude-code #78690](https://github.com/anthropics/claude-code/issues/78690). In #77752 maintainer bcherny captured the output and found Claude Code *does* disable mouse tracking, focus reporting and bracketed paste before suspending and re-enables them on `fg`; the actual bug was not leaving the fullscreen alternate screen, and VTE terminals turn wheel events into Up/Down keys while the alternate screen is active; fix: leave the alternate screen on suspend and re-enter on resume "as vim and less do"; reporter confirmed fixed in 2.1.266; workarounds `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1`, `reset`, or a zsh `precmd` hook printing `\033[?1000l\033[?1002l\033[?1003l\033[?1006l\033[?1007l` — [claude-code #77752](https://github.com/anthropics/claude-code/issues/77752)
- Textual's `action_suspend_process` sends SIGTSTP on Unix and is a no-op on Windows and Textual Web — [Textual App API](https://textual.textualize.io/api/app/)

#### Handing the terminal to an editor, pager or shell command and taking it back
- Ratatui recipe: `LeaveAlternateScreen` → `disable_raw_mode()` → `Command::new("vim").status()` → `EnterAlternateScreen` → `enable_raw_mode()` → `terminal.clear()`; pause the TUI's event handlers first ("Otherwise Vim won't get full control of keybindings"); beware the child's own terminal queries answering into your stdin — [ratatui spawn-vim](https://ratatui.rs/recipes/apps/spawn-vim/)
- Bubble Tea `Exec`/`ExecProcess` pause the Program for "spawning other interactive applications such as editors and shells"; `ReleaseTerminal` restores the original state and cancels the input reader; `RestoreTerminal` re-initialises the reader, restores the running state, repaints and checks for a resize — [pkg.go.dev bubbletea](https://pkg.go.dev/github.com/charmbracelet/bubbletea)

#### Synchronized output and alternate-screen policy
- Synchronized output: `CSI ? 2026 h` begins and `CSI ? 2026 l` ends a frame; query with DECRQM `CSI ? 2026 $ p` (reply `CSI ? 2026 ; Ps $ y`, `Ps` 0 or 4 = unsupported; no reply also = unsupported; GNOME Terminal replies 4); the spec sets no fixed timeout for a missing end sequence — "no real consensus… implementers must decide" — and notes "a timeout that is too short is no worse than having no synchronized output"; supported by Windows Terminal, Contour, mintty, foot, VTE, iTerm2, Kitty, Warp, Alacritty ≥ 0.13, Ghostty; WezTerm not yet; xterm.js unclear — [synchronized output spec (gist)](https://gist.github.com/christianparpart/d8a62cc1ab659194337d73e399004036). Claude Code probes support at startup and notes tmux through the 3.6 series lacks it — [Claude Code fullscreen](https://code.claude.com/docs/en/fullscreen); Codex wraps every draw in `stdout().sync_update(...)` — [tui.rs](https://github.com/openai/codex/blob/main/codex-rs/tui/src/tui.rs)
- Codex `tui.alternate_screen = auto` avoids the alternate screen inside Zellij to preserve scrollback — [Codex config reference](https://learn.chatgpt.com/docs/config-file/config-reference); Claude Code's `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1` forces the classic renderer, and `tmux -CC` (iTerm2 integration) is explicitly incompatible with its fullscreen mode (wheel does nothing, double-click can corrupt terminal state) — [Claude Code fullscreen](https://code.claude.com/docs/en/fullscreen)

### Inferences
- Restore order that follows from the findings: end any open synchronized update → pop kitty flags (`CSI < u`; on process exit also send the clear-all form) and `CSI > 4;0 m` → disable mouse (1000/1002/1003/1006/1007), focus (1004) and bracketed paste (2004) → leave the alternate screen (1049) → show cursor (`?25h`) and reset cursor style (`CSI 0 q`) → `tcsetattr` with the termios saved at startup → flush. Doing cooked mode last means a shell prompt never sees a half-restored keyboard. The routine must be idempotent and must never throw (it runs from panic/signal context).
- For .NET: `Console` offers no raw mode or termios control on Unix, so Corvid needs `tcgetattr`/`tcsetattr` via P/Invoke (or a PTY/termios helper) and `PosixSignalRegistration` for SIGINT/SIGTERM/SIGHUP/SIGTSTP/SIGCONT/SIGWINCH; the SIGTSTP handler should restore, then re-raise with the default disposition (ncurses/Bubble Tea pattern), and the SIGCONT path must re-apply modes unconditionally (Codex's lesson), re-query the size and repaint. Verify .NET's `PosixSignal` enum coverage (not checked in this pass).
- Avoid `REPORT_EVENT_TYPES` unless key-release events are needed — it is the source of every documented kitty leak; if it is used, drain stdin for a bounded time after disabling it before handing the terminal back.
- Child-process handoff should be a single `using`-style scope that (a) pauses the input reader, (b) runs the restore routine (optionally keeping raw mode), (c) runs the child with inherited stdio, (d) re-applies modes, re-queries the size, discards any query replies that arrived, and (e) forces a full repaint. The Gemini #18029 failure (spawn with inherited stdio while the TUI still owns the terminal) is exactly what this scope prevents.
- A crash-loop fallback like Claude Code's (record "started successfully" after the first frame + 10 s; fall back to a simpler renderer after repeated failures) is cheap insurance for a new renderer.

### Gaps
- None of the surveyed frameworks document SIGHUP handling; ncurses's `lib_tstp.c` does not handle it either. Whether to attempt a restore on SIGHUP (the terminal is usually gone) is a design choice without a documented precedent here.
- Bubble Tea's exact exit sequence bytes are emitted by the renderer/flush code, which was not read; only the termios restore was confirmed.
- Whether Claude Code's classic (Ink) renderer pops kitty flags on all exit paths is inferred from Ink's `finishUnmount`, not verified in Claude Code.
- .NET-specific primitives (`PosixSignalRegistration` signal coverage, termios P/Invoke patterns) were not researched in this pass.

## Key question 4 — Long sessions, huge outputs, and keeping tool output from altering the terminal

### Takeaway
The documented degradation is the same across Ink-based CLIs: when the live region grows beyond the viewport the renderer repaints the whole transcript every tick (Claude Code #21567: `blit=0, write=625433`, rows growing 23→4771, 100 % CPU, input frozen 30 s+; #1913/#769/#9935: flicker and 4,000–6,700 scroll events/s), and memory grows from retained buffers rather than rendering (#32920: 14,002 ArrayBuffers, 6.8 GB after 14.5 h). The fixes in production are architectural: Codex writes finished lines into native scrollback through a DECSTBM scroll region and keeps only a small live viewport, with a 120 FPS draw clamp and middle-truncation of tool output by byte/token budget; Claude Code's fullscreen renderer virtualises the transcript ("only renders messages that are currently visible… memory stays constant") and caps bash output at 30,000 chars; Gemini runs shell output through a headless xterm with a 50,000-line scrollback, a 2,000-line UI window, a 16 MB cap and ~68 ms render throttling, and serialises cells to styled tokens so no raw escape sequence ever reaches the terminal. Escape-sequence injection from tool/LLM output is a live, CVE-backed class (OSC 52 clipboard, OSC 8 link spoofing, hidden instructions), and Trail of Bits found Claude Code 0.2.76 did no filtering; the robust answer is to render untrusted bytes through an emulator or strip every 0x1b.

#### Strategies in production
- Codex inline model — "commit finished rows to native scrollback, keep a small live viewport": `insert_history.rs` sets a DECSTBM scroll region (`ESC[top;bottom r`) covering rows `1..area.top()`, uses Reverse Index (`ESC M`) to shift the viewport down when it is not at the bottom, moves to the bottom of the region and prints `\r\n` + line for each history line (so the region scrolls into scrollback), then resets the region (`ESC[r`) and restores the cursor; `MoveTo` is used instead of ratatui's cursor API so the terminal's cached cursor stays accurate; a "full-screen" insertion mode exists because partial scroll regions are unreliable in some environments and to preserve Zellij's soft wrapping; on Windows `SetScrollRegion` panics via the WinAPI path so ANSI must be used; failed batches are not retried "to avoid duplicating output"; wrap policies `PreWrap` (URL-only lines left unbroken so terminals can linkify; continuation rows indented) vs `Terminal` (let the terminal soft-wrap); row counts use display width — [insert_history.rs](https://github.com/openai/codex/blob/main/codex-rs/tui/src/insert_history.rs); `insert_history_lines_with_wrap_policy` queues lines, `flush_pending_history_lines` writes them above the viewport, `scrollback.grow_viewport` scrolls when the viewport would overflow, `draw_with_resize_reflow` rebuilds history on shrink — [tui.rs](https://github.com/openai/codex/blob/main/codex-rs/tui/src/tui.rs); the vt100-backed test asserts committed rows land in the emulated screen — [vt100_live_commit.rs](https://github.com/openai/codex/blob/main/codex-rs/tui/tests/suite/vt100_live_commit.rs)
- Codex frame budget: `frame_rate_limiter.rs` "clamps draw notifications to a maximum of 120 FPS to avoid wasted work" (`MIN_FRAME_INTERVAL` = 8,333,334 ns); requests inside the interval are moved to the earliest allowed time so bursts collapse into one draw — [frame_rate_limiter.rs](https://github.com/openai/codex/blob/main/codex-rs/tui/src/tui/frame_rate_limiter.rs); every draw is wrapped in a synchronized update — [tui.rs](https://github.com/openai/codex/blob/main/codex-rs/tui/src/tui.rs); `tui.raw_output_mode` switches to raw scrollback for copy-friendly selection — [Codex config reference](https://learn.chatgpt.com/docs/config-file/config-reference)
- Codex tool-output truncation (`codex-rs/utils/output-truncation`): a `TruncationPolicy` is a byte or token budget (line count is reported, never limited); a 1.2× serialization allowance; text inside the budget passes through; otherwise middle truncation (`truncate_middle_chars` / `truncate_middle_with_token_budget`) with a prepended header "Warning: truncated output (original token count: N)" and "Total output lines: M"; structured content lists share one budget (images/encrypted items kept at zero cost, dropped items summarised as "[omitted N text items …]"); MCP results are reduced to a text preview that is shrunk repeatedly until the serialised result fits — [output-truncation lib.rs](https://github.com/openai/codex/blob/main/codex-rs/utils/output-truncation/src/lib.rs)
- Claude Code classic renderer = Ink: `<Static>` renders items once "above everything else" and never re-renders them (the mechanism for pushing finished output to scrollback); `maxFps` default 30 (34 ms throttle, leading+trailing); `incrementalRendering` (default `false`) "updates only changed lines"; `shouldClearTerminalForFrame()` takes the full-clear path when the frame overflows the viewport; `homeAndEraseDown` (`cursorTo(0,0)+eraseDown`) "must clear only what is visible", avoiding the scrollback-erasing `clearTerminal`; `fullStaticOutput` is replayed only on the alternate screen "because there is no scrollback to keep it in" — [Ink README](https://github.com/vadimdemedes/ink); [ink.tsx](https://github.com/vadimdemedes/ink/blob/master/src/ink.tsx)
- Claude Code fullscreen renderer: alternate screen; virtual scrolling (`CLAUDE_CODE_DISABLE_VIRTUAL_SCROLL=1` "render every message in the transcript" exists for blank-region bugs); sends only changed cells (`CLAUDE_CODE_ALT_SCREEN_FULL_REPAINT=1` for ConPTY hosts that "coalesce these positioned writes incorrectly"); collapsed tool results expand on click; transcript mode `[` writes the whole conversation into native scrollback ("Long sessions may pause for a moment"), `v` opens it in `$EDITOR`; `/focus` shows only the last prompt, a one-line tool summary and the final response; auto-follow pauses when scrolled up with a "Jump to bottom · N new messages" button — [Claude Code fullscreen](https://code.claude.com/docs/en/fullscreen); [Claude Code env vars](https://code.claude.com/docs/en/env-vars)
- Claude Code output caps: `BASH_MAX_OUTPUT_LENGTH` default 30000 chars (max 150000; `bashOutputMaxChars` setting takes precedence), `CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS` default 25,000 — [Claude Code env vars](https://code.claude.com/docs/en/env-vars)
- Gemini CLI shell pipeline: PTY (80x30) → `@xterm/headless` with 50,000-line scrollback → output chunks processed sequentially with rendering throttled to ~68 ms → UI gets `serializeTerminalToObject` for a window of `maxSerializedLines` (default 2,000; unchanged frames skipped) → the model gets `getFullBufferText` (soft-wrapped lines rejoined, trailing whitespace trimmed, capped at 16 MB keeping the tail); the non-PTY fallback caps at 16 MB (oldest data dropped with a `GEMINI_CLI_WARNING`) and strips ANSI; binary output is sniffed from the first ≤4 KB and replaced by `binary_progress` byte counts; backgrounded commands log to a temp file with ANSI stripped; `tools.truncateToolOutputThreshold` default 40000 chars — [shellExecutionService.ts](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/services/shellExecutionService.ts); [Gemini CLI settings](https://geminicli.com/docs/cli/settings/)
- Gemini's serializer emits structured tokens (text + `bold/italic/underline/dim/inverse` + `fg`/`bg` as `#rrggbb`), merging identical adjacent cells; it reads rendered cell state only, so "the code never emits raw escape sequences" — [terminalSerializer.ts](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/utils/terminalSerializer.ts)
- Frame-rate defaults elsewhere: Bubble Tea renderer default 60 FPS, values over 120 capped at 120 (`WithFPS`) — [pkg.go.dev bubbletea](https://pkg.go.dev/github.com/charmbracelet/bubbletea); Textual `TEXTUAL_FPS` default 60 — [Textual constants](https://textual.textualize.io/api/constants/)
- Resize/re-wrap cost: Codex rebuilds history on shrink (`draw_with_resize_reflow`) and uses a heuristic to shift the viewport when the cursor row moves during a resize — [tui.rs](https://github.com/openai/codex/blob/main/codex-rs/tui/src/tui.rs); Claude Code's classic renderer re-renders the full output when it overflows (#1913, #769 above); the Ghostty 10M-line scrollback anecdote in #9935 (194 GB) shows terminal-side scrollback also has a cost — [claude-code #9935](https://github.com/anthropics/claude-code/issues/9935)

#### Binary/control characters in tool output and terminal escape injection (security)
- Baseline research (dgl, Sept 2023): OSC 52 clipboard read/write (xterm, most distros disable reads); OSC 8 hyperlinks in `less` + mintty DECRQSS echo → command execution from `git log` on a crafted commit; title-reporting echo attacks (ConEmu CVE-2022-46387/CVE-2023-39150; WezTerm and SwiftTerm enabled reporting by default); DECRQSS echoback in iTerm2 (CVE-2022-45872), mintty (CVE-2022-47583), SwiftTerm (CVE-2022-23465); OSC 50 (xterm CVE-2022-45063, mintty CVE-2023-39726); Windows Terminal OSC 9;9 (CVE-2022-44702), urxvt OSC 20 (CVE-2022-4170), kitty notifications (CVE-2022-41322), Apple Terminal OSC 7 DNS leaks; mitigation for applications: "Escape output before printing it. At minimum, strip or escape ESC"; `top`, `tar`, `ksh`, Python's `http.server` were vulnerable because they printed raw data — [dgl.cx ANSI terminal security](https://dgl.cx/2023/09/ansi-terminal-security)
- "Terminal DiLLMa" (Johann Rehberger, 2024-12-06): LLM output can carry escape sequences — demonstrated flashing/coloured text, bell, title changes, cursor moves and screen clears, hidden text and backspace erasure, clipboard writes ("could lead to code execution if the trailing newline was kept"), clickable links carrying prompt-context data, and zero-click DNS requests via macOS Terminal; mitigations: encode control characters by default (`cat -v` style) with an explicit opt-in for raw sequences, allow-list expected characters, test every context, treat LLM output as untrusted — [embracethered.com](https://embracethered.com/blog/posts/2024/terminal-dillmas-prompt-injection-ansi-sequences/); the arXiv paper "Trust No AI" (2412.06090) names the class and suggests caret notation — [arXiv 2412.06090](https://arxiv.org/pdf/2412.06090); NVIDIA garak ships `ansiescape` probes (AnsiEscaped/AnsiRaw) to test whether a model emits them — [garak docs](https://reference.garak.ai/en/stable/probes/ansiescape.html)
- Trail of Bits (2025-04-29): Claude Code 0.2.76 "does not offer any filtering or sanitization for tool descriptions and outputs containing ANSI escape sequences"; demonstrated hidden instructions via invisible colours, cursor moves overwriting text, screen clearing hiding a reverse-shell instruction, and OSC 8 links whose text differs from the target; recommendations: do not pass raw tool output to the terminal, sanitise by disabling escape sequences ("replace every byte with hex value 1b"), add standard filtering to MCP SDKs — [Trail of Bits blog](https://blog.trailofbits.com/2025/04/29/deceiving-users-with-ansi-terminal-codes-in-mcp/)
- CVE-2026-47090 (Claude HUD ≤ 0.0.12, a Claude Code status-line plugin): OSC 8 hyperlinks were built "using raw cwd and branchUrl values without stripping control characters", letting a crafted directory name or branch URL change colours, forge prompts, write the clipboard via OSC 52, or trigger outbound HTTP on click; CWE-150; fixed in commit 234d9aa — [OSV CVE-2026-47090](https://osv.dev/vulnerability/CVE-2026-47090)
- CVE-2026-48725 (Warp, 2021-04 → fixed 0.2026.05.06.15.42.stable_01): "allows terminal output to request access to the local system clipboard" via OSC 52 — reads and writes without a confirmation step; CWE-276; CVSS vector AV:N/AC:L/PR:N/UI:R with high confidentiality/integrity impact — [OSV CVE-2026-48725](https://osv.dev/vulnerability/CVE-2026-48725)
- A library-level example: the `pickem` TUI library passed strings straight to stdout, enabling OSC 52 writes and cursor-movement rewrites of earlier lines; 1.0.7 added sanitisation "at every render boundary" — [SecureLayer7 write-up](https://securelayer7.net/lab/pickem-terminal-escape-sequence-injection-unsanitized-labels)
- Production mitigations observed: Codex filters control characters out of untrusted history text (tests confirm raw ESC, OSC and C1 bytes are never emitted) and adds OSC 8 only for trusted, semantically annotated links — [insert_history.rs](https://github.com/openai/codex/blob/main/codex-rs/tui/src/insert_history.rs); Gemini renders shell output through xterm-headless and serialises cells to tokens, so output "is data (text plus style flags and hex colors) rather than control sequences" — [terminalSerializer.ts](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/utils/terminalSerializer.ts); `XTerm.NET` parses OSC 52 and surfaces it as a `ClipboardReadRequested` event rather than acting on it — [XTerm.NET repo](https://github.com/tomlm/XTerm.NET)
- Clipboard writes by the *app itself* are terminal-gated: Claude Code falls back to OSC 52 over SSH and notes iTerm2 blocks OSC 52 until "Applications in terminal may access clipboard" is enabled; GNU screen printed base64 into the window for selections > ~570 chars before 2.1.219 — [Claude Code fullscreen](https://code.claude.com/docs/en/fullscreen)

### Inferences
- For a long-lived agent session the transcript must not live in the renderer's live region. The two proven shapes are (a) Codex's inline model — finished blocks are written once into native scrollback via a scroll region and forgotten, the live viewport is a few rows — and (b) Claude Code's fullscreen model — alternate screen with a virtualised transcript and explicit "write to scrollback"/"open in editor" escape hatches. (a) keeps native search/selection and screen-reader friendliness; (b) gives mouse, flicker-free redraws and flat memory. Either way memory should be bounded by keeping rendered lines (not raw tool output) for the visible/recent window and spilling the rest to the on-disk transcript.
- Large tool output needs three independent caps: what is streamed to the screen (window of N lines with "expand" that opens a pager or the on-disk file), what is kept in memory (ring/scrollback limit like Gemini's 50,000 lines or a byte cap), and what is sent to the model (head/tail middle truncation with a header, like Codex, or a char cap like Claude's 30,000) — Gemini #27738 shows that missing the third cap wedges the session permanently.
- Render budgets: coalesce model/tool events into frames at a fixed cadence (Ink 30, Bubble Tea 60, Codex ≤120 FPS), wrap each frame in synchronized output when the terminal reports support, write frames from a dedicated writer with backpressure (never a synchronous 100 KB+ write on the event loop — #23987), and stop the timer entirely when nothing animates (#78969).
- Re-wrapping on resize is cheapest when wrapped lines are cached per width and only the visible window is re-wrapped eagerly; history already committed to scrollback (model a) is left to the terminal.
- Sanitisation policy for Corvid: treat every byte from tools, MCP servers and the model as untrusted; either render through an emulator (XTerm.NET → styled cells, like Gemini) or strip all C0 controls except `\n`/`\t`, all C1 bytes, and every ESC-initiated sequence, re-adding only Corvid's own SGR and OSC 8 for links it constructed; never forward OSC 52, title, DECRQSS or query sequences from untrusted content; and encode what was stripped (caret notation) so the user can see that something was there.

### Gaps
- No maintainer-confirmed root cause exists for Claude Code #21567/#1913/#769; the fullscreen docs are the implicit acknowledgement.
- Codex TUI-specific long-session memory/latency data is thin; most Codex "memory" issues are the Electron desktop app, and #52555's surface is unconfirmed.
- Whether Claude Code now sanitises escape sequences in tool output (post Trail of Bits, April 2025) was not verified.
- No measured numbers for the cost of re-wrapping a long transcript on resize were found.
- The exact head/tail split used by Codex's middle truncation lives in `codex_utils_string`, which was not read.
